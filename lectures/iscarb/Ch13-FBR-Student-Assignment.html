What distinguishes an unsupported answer from a stronger one?

Different practice example · weak: “The page hides the record, so authorization works.”

Stronger: For a different booking record, user A requests user B’s identifier directly from the API. The proposed test expects denial and no protected content; it records the actor, object and inspected response.

The stronger answer names a mechanism, its scope and inspectable evidence. It does not certify a real system. Your assessed answer must address this task’s own facts.

2 · PART A · 20 MINUTES

Assessed scenario · fictional teaching case

A fictional university portal has student and staff roles. Students should access only their own project files; staff should access only the groups assigned to them. The interface hides other students’ files. A developer reports that every ordinary upload/download test passed. The API receives a project identifier in the request, but the brief contains no cross-user authorization test. Log retention is configured, but nobody has reviewed a sample for sensitive content. You recommend release, restricted access, or hold.

Teaching simulation. Use only the supplied facts. You may calculate from them. Do not invent additional test results, thresholds or completed audits. If you propose extra evidence or a new threshold, label it proposed.

Keep the complete written response to about 180–260 focused words; use compact tables or notation. Include the source application and transfer answer in that budget. The executable log replaces prose about hypothetical test execution. No external experiment is required. State facts, assumptions and proposed evidence separately. Quote or cite the assigned source precisely; explain its role. Report actual study time at the end.

A1 · FIT · 1 POINT

Identify one asset, one threat and one plausible vulnerability from the brief. Keep a suspected weakness distinct from a demonstrated exploit.

SMALL EXECUTABLE LAB · PART OF THE EXISTING ARTIFACT

Server-side access tests

Write at least three cases. Each case is a JSON object with name, actor (student:ID or staff:GROUP), object (project:OWNER@GROUP), path (ui or api) and expected (allow or deny). A student may access only their own project; staff may access only projects in their assigned group. Include an allowed and a forbidden request on the api path. Predict each decision before running.

Budget 15–20 minutes within the assignment. The run log replaces a paragraph describing hypothetical execution. Keep your actual failures; explain any wrong prediction. Passing tests is not an automatic grade.

Inspect the teaching-model rules
// One request is decided at a time.
// Rule: a student may access a project they own; staff may access projects in their assigned group.
// Baseline: the rule is applied only where the interface lists links (path "ui");
//           the API serves any project identifier it receives.
// Corrected: the server checks the actor against the object on every path.
// No sessions, logs, network or real accounts are modelled.

Replace the uppercase placeholders; they are a schema illustration, not runnable answers.

Both runs are required; this is an offline teaching model.



A2 · TEST · 1 POINT
Write two test cases: one allowed request and one forbidden request. State the actor, input/object, expected result and evidence to inspect. The tests are proposed, not executed.


A3 · BOUND · 1 POINT
State which roles, objects and access paths the recommendation covers. Name an untested path and a reopening trigger.


A4 · ACT + EVIDENCE · 1 POINT
Choose a bounded release action. Link a concrete server-side control to the tests and identify the reviewer.
Name the relevant test/log/audit, the conditions it must cover, who checks it, and what evidence is still missing. Do not describe requested evidence as if it already exists.




ASSIGNED SOURCE APPLICATION · INCLUDED IN THE EXISTING RUBRIC
Write the source slide number, explain the concept in your own words, and identify the specific part of your artifact it supports or challenges. Use the assigned pages above. A citation alone is insufficient.
TRANSFER CHECK · SCORED WITH FIT
A file-access policy says “students access only their own files.” Explain how a misuse case differs from an ordinary use case, and write one testable server-side requirement.
